# モーニングジャーナル観測 仕様（v1 候補）

状態: **Acceptance Test 中（未凍結）**。本人が実データの出力を読み「これで試す」と判断した時点で v1 として凍結し、
2〜3か月の試行期間に入る。凍結後に下記の値を変える場合は「v2」として日付を記録し、v1 の期間と混ぜて比較しない。

目的: 人生を評価することではなく、自分が書いた記録を Python と AI で整理し、本人が自分の変化を発見できるかを検証する。

## 1. データの正本と4分類（混ぜない）
| 分類 | 中身 | 置き場所 |
|---|---|---|
| A 生データ | Discord #モーニングジャーナル の本人の投稿・返信（Bot の投稿は除外） | Discord（非公開サーバー）／シート同期（GAS） |
| B Python の事実 | 書いた日数・文字数・語の出現日の割合・表現の出現率・共起・根拠 | 「週次観測」タブ（要約）／「観測詳細」タブ（全件） |
| C AI の仮説 | Gemini が語の増減だけから出した「変化の筋」（根拠語つき） | 「仮説確認」タブの AI仮説(C) 列／「観測詳細」タブ |
| D 本人の確認 | ○ △ × ／ どれも違う ／ 別のこと ／ 見えた・見えない ／ 未回答 | 「仮説確認」タブの 本人回答(D)・本人コメント(D)・回答日時(D) 列 |

- **正本は Discord だけ**。Apple メモはその場の走り書き用で、観測の対象にしない（取り込みも手動転記も必須にしない）
- × と「どれも違う」は消さない（AI 仮説が外れた履歴）。未回答は「未回答」＝保留であり、否定として扱わない
- GitHub（公開リポジトリ）・公開シート・公開 URL には A〜D のいずれも置かない

## 2. 本人確認（○△×）
- 場所: #週刊まとめ の週次レビュー（Discord）への本人の返信。書式は1行ずつ、コメントは任意
  - `1 ○` `2 △` `3 ×`（月次の仮説は `M1 ○`）／ `どれも違う` ／ `別のこと：〇〇` ／ `見えた` ／ `見えない`
- 次の週次レビューを作る直前に、前回のレビュー以降の本人の投稿を読み、前回分の D 列に反映する
- 未回答の催促・再送はしない。同じ項目に複数回答した場合は後の回答を採用
- 実装: `scripts/journal_confirm.py`（`weekly_mindmap.py` から呼ぶ）

## 3. 観測の構造（固定。結果が悪くても窓は増やさない）
- 観測窓: 出来事 ／ 変化 ／ 継続 ／ 確認 ＋ ✓（行動・完了）＋ ★（本人が重要と判断）
- 「今週は大きな変化なし」「十分な記録量がないため、明確な差分は確認できません」は正常な出力
- 週次は廃止しない（週次と月次のどちらが役に立つかは、本人が読んで判断する）

## 4. v1 の値（凍結対象。`scripts/journal_observe.py`）
| 項目 | 値 |
|---|---|
| 比較 | 今週 vs 直前4週（＋前週を併記）、履歴 7週／月次は直近28日 vs 前28日 |
| 語の増減 | 出た日の割合の差 30pt 以上 かつ 期待日数との差 1.5日以上 |
| 新規・増加の最低日数 | 週 2日／月 3日 |
| 出てこなかった | 比較期間の2期間以上に出ていて、期待日数 2日以上 |
| 継続・安定 | 3期間連続（書かなかった週は数えない）、割合の差 15pt 未満なら安定 |
| 表現の増減 | 出現率 1.5倍以上 or 0.67倍以下 かつ 回数合計 4以上 かつ 期待回数との差 3以上 |
| 記録量不足の表示 | 週に書いた日 3日未満 |
| AI に渡すもの | 語の増減（減少・消失／新規・再登場・増加）と出現日数だけ。片側最大12語。本文・抜粋は渡さない（10・11章） |
| 仮説の形式 | 根拠語必須（渡した一覧の語のみ）・「〜かもしれない」等の形・最大3件。指示・断定・点数・引用らしい文は除去 |
| 除外 | Bot の投稿（author.bot）、旧投稿ガイドラインの固定見出し |

## 5. ✓ と ★（自動判定しない）
- ✓: 本人が完了と明示したものだけ。月次レビューで本人が確定するのを基本とする
- ★: 本人が重要と明示したものだけ（月に最大3つ）。手帳だけに書いた★はデジタル比較に入らない
- 保存構造（未実装・必要になったら作る）: シート「月次確定」タブ ＝ 月 ／ 種別(✓ or ★) ／ 内容 ／ 確定日

## 6. 継続テーマ
- Python は「安定して続いている／続いている」を候補として出すだけ。登録は本人のみ、自動登録しない、最大5件
- 置き場所（未実装）: シート「継続テーマ」タブに本人が手で書く。管理画面は作らない

## 7. 四半期比較（将来仕様として固定）
- 使ってよい材料: ① 生データから Python が計算し直した数値 ② 記録上の差分 ③ 本人の ○△× ④ 本人の ✓ ⑤ 本人の ★
- 月次の AI 要約をさらに AI で要約する「要約の要約」はしない。未確認の AI 仮説は参考情報であり、事実として扱わない

## 8. 試行期間の評価指標（4つに絞る）
1. ジャーナルを書いた日数（週ごと）
2. AI 仮説への回答率（未回答以外の割合）
3. 「×」と「どれも違う」の件数（AI の仮説が外れた量）
4. 「見えた」と答えた週の数

## 9. Library（長期保存）の置き場所
- 公開リポジトリ・公開シート・公開 URL には置かない。スプレッドシートは共有設定が「制限付き」であることを本人が確認する

## 10. 表示層（2026-09-30 再設計。Acceptance Test 不合格を受けて）
- 不合格の原因: 計測ではなく表示。語の統計（O-項目・表現率・共起）がそのまま平たく並び、本人が意味を組み立て直す必要があった
- Discord の主な本文に載せるのは、次のものだけ
  - 「変化の筋」最大3件: Gemini の仮説、以前の抜粋、今期の抜粋、確認記号（`1 ○` / `1 △` / `1 ×`）
  - 抜粋は Python が元の記録から、根拠語を含む日を決定論的に選んで付ける（Gemini には作らせない）。
    以前の記録が無ければ「該当する記録なし」
  - 記録量が少ない週の注意、回答方法の案内、詳細タブへの案内
- 主な本文に載せないもの: O-番号、千字あたりの比率、共起の回数、「3/4日」などの頻度、語の出入りの一覧、PNG
- 計測値は削除しない。「観測詳細」タブ（非公開）に全件を残す
  - 内容: 観測項目・根拠日付・抜粋・URL・表現率・共起・語の区分・AI に渡した機械データ・AI の状態・AI 仮説と抜粋
- 語をつなげてまとまりを作ること（同時出現のグラフなど）は Python ではしない。まとめ方の候補を出すのは Gemini、確かめるのは本人
- 実装: `journal_observe.diff_for_ai / interpret_diff / excerpts_for / compose_review / detail_rows`

## 11. Gemini への送信境界
- 送ってよいもの: 減少・消失した語、新規・再登場・増加した語、それぞれの出現日数、書いた日数（`diff_for_ai` の出力だけ）
- 送らないもの: 日記本文、抜粋、URL、Discord のメッセージ本文、前週だけ出た語、安定・継続の語、表現率、共起
- 日記を Gemini に送りうる経路はすべて停止した
  - `journal_review.analyze`: 手元の簡易ルールだけで構造化する
  - `generate_monthly_mindmap`: AI 要約を作らず雛形のみ
  - `generate_daily_report`: 停止
- 検証: `tests/test_review_layer.py`
  - 送信内容に日記の文の断片・URL が含まれないこと（週次と月次を通しで実行して確認）
  - 他の3経路が Gemini を呼ばないこと
- 注意: 語の一覧にも固有名詞は含まれる。利用するキー（無料枠など）の規約で、送信内容がどう扱われるかは本人が確認する

## 12. Gemini が使えないとき
- 対象: キー未設定、429 などの API エラー、タイムアウト、JSON でない応答、使える仮説が無い応答（断定・一覧に無い語の引用など）
- 表示: 「【前期からの主な変化（機械集計）】減少・消失：… ／ 新規・増加：…」（片側最大8語）と、
  「AIによる仮説生成は利用できませんでした。上は語の機械的な並びであり、意味付けではありません」の注記だけ
- 計測値の一覧（O-項目など）には戻さない。語の増減が無ければ「変化候補なし」（正常な出力）

## 13. Acceptance Test モード
- 週次ワークフローを手動実行するとき、run_mode=acceptance（環境変数 JOURNAL_RUN_MODE=acceptance）で動かす
- 書き込み先: 「AT_週次観測」「AT_観測詳細」「AT_仮説確認」タブだけ。本番のタブ（W39 の行など）には書かない
  - 観測詳細は実行 ID（AT-日時）付きで追記し、過去の結果を消さない
- Discord: 見出しに「【Acceptance Test】」を付けて投稿する。ピン留めと、#週刊まとめ の返信の読み取りはしない
